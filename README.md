# Better Grok Ask

点击 X 帖子上那个 Grok 小图标时，**拦住** X 的原生行为，改为把帖子链接预填进 Grok 输入框，**不发送** —— 你自己补问题、自己按发送。

## 它解决什么

X 原生点这个图标的行为是：

- 就地打开 Grok 抽屉，并把**这条帖子作为卡片消息直接发出去**（不经你确认）；
- 即使它临时把链接放进输入框，**也没有尾随空格** —— 你接着打字，第一个词会粘在链接后面变成 URL 的一部分。

本扩展把这两件事都改掉：不发送、不产生帖子卡片，输入框里留一条 `链接 + 空格`，光标停在末尾。

## 行为

| 触发 | 结果 |
| --- | --- |
| 帖子的 Grok 图标（桌面） | 阻止 X 的原生处理 → 点右下角悬浮 Grok 按钮打开抽屉 → 预填 `https://x.com/<用户>/status/<id> `（不发送、无卡片） |
| 帖子的 Grok 图标（窄屏 / 移动端） | 当前标签页跳转 `/i/grok` → 预填同样内容（不发送） |
| 找不到悬浮按钮的构建 | 退回新标签页打开 `/i/grok` 并预填（不会出现"点了没反应"） |
| **直接点悬浮 Grok 抽屉按钮** | **不做任何预填**（这是刻意的：那是通用入口，不属于某条帖子） |
| 其它任何打开 Grok/抽屉的按钮（左侧导航 Grok、私信、帖子溢出菜单、生成图片等） | 完全不处理 |

## 安装

1. 打开 `chrome://extensions`，开启右上角**开发者模式**
2. **加载已解压的扩展程序** → 选择本目录（含 `manifest.json` 的那一层）
3. 改动代码后必须点该扩展的**重新加载**；若行为没变，点**移除**后重新加载目录

## 设置

点扩展图标（或工具栏 → 扩展 → 选项）打开设置页：

- **在帖子链接后加一个空格**（默认开）。关掉后只写链接本身，此时提示词里的第一个词会与 URL 相连，X 也可能把它识别为"纯帖子链接"。

## 工作原理

所有关键机制都在真实 x.com（登录态）上实测过，不是按文档推测的。

**1. 拦截而不是共存** —— `src/content.js`

在 `document` 的捕获阶段监听点击，命中后 `preventDefault()` + `stopPropagation()`，X 自己的处理器完全不会执行，因此它那条"发送帖子卡片"的流程根本不会启动。

**2. 只认帖子里那个图标** —— `src/dom.js`

- 容器：最近的 `<article>`；新构建里 `<article>` 没有 `data-testid`，所以不依赖 testid
- 入口：`aria-label` / `title` 含 Grok（中英文均可，如 `Grok 操作`、`Ask Grok`），且排除图片生成类（`生成图片`、`imagine`）；或 `data-testid` 形如 `grokPost` / `grokActions`
- 永久链接：取该帖子自己的 `/status/<id>` 链接，排除引推里的链接，也排除新构建追加的无用户名形态 `/i/status/<id>`；只有后者时用帖子里的作者链接补回用户名

**3. 用 X 自己的悬浮按钮打开抽屉** —— `src/composer.js`

右下角那个和「聊天」并排的悬浮按钮是抽屉的开关，点它得到的是**全新会话、不带帖子卡片**。它的标识**不可靠**：抽屉从未打开过时它带 `data-testid="GrokDrawerHeader"` 和 `aria-label="Grok"`，但一旦用过抽屉、收起后，它会被重新渲染成**没有 `aria-label`、没有 `data-testid` 的裸按钮**。所以定位方式是"先按标识找，找不到就按结构找"——`[data-testid="GrokDrawer"]` 这个条（收起时约 57px 高，展开时约 500px）里的那个按钮。用错判据的表现就是「输入框有内容／收起之后再也唤不起抽屉」。

判断"抽屉是否已开"只看**Grok 输入框是否存在**（`findComposer()`）——`[data-testid="GrokDrawer"]` 那个元素**收起时也在**（就是右下角那条 400×57 的横条，里面装着悬浮按钮），按它的存在或宽度判断必然误判。

还有一点：悬浮按钮在开合过程中会被拆掉重建，**要等它出现再点**，不能只采样一次就放弃。

抽屉打开后，每次预填前还会点一次抽屉头部 X 自己的**「新聊天」**：上一轮对话里的内容（或仍在流式回复的会话）会持续重渲染输入框并把写入吞掉——这正是"已经用它解释过一个帖子后，再点别的帖子没反应"的原因。按钮因语言/状态不可得时，退化为"清空输入框再写"。

**4. 只能用编辑管线写入**

Grok 输入框是 `<textarea>`，但它只接受浏览器编辑管线产生的输入：

```js
// 无效：X 的状态收不到，下一次渲染会把值抹掉
el.value = text;
el.dispatchEvent(new Event('input', { bubbles: true }));

// 有效
el.focus();
el.setSelectionRange(el.value.length, el.value.length);
document.execCommand('insertText', false, text);
```

写入还会**等输入框内容稳定 400ms** 再动手（避开 X 打开抽屉时的重建），并且要**连续 600ms 不被重置**才算成功；否则重试，最多 20 秒。

**5. 尾随空白要单独插一次**

较长的 `insertText` 会吞掉结尾的空白，所以拆成"正文 + 空白"两次插入；空白依次尝试 `' '` → `\u00A0`（不间断空格同样满足 `\s`，也是 X 判定"纯链接"时接受的结尾空白）。

**6. 跨导航传递待填文本** —— `src/background.js`

窄屏跳页、或回退开新标签页时，原文档会被卸载，所以文本先经 `chrome.storage.session` 存下，由 `/i/grok` 页面的内容脚本取走并写入，取走即清除（30 秒过期）。

> 顺带一个事实：X 自己的深链 `/i/grok?text=<prompt>` 在这套构建里**并不会预填输入框**（实测 6.5 秒后仍为空），所以文本一律由扩展写入。

## 文件

```
manifest.json         MV3 清单（storage 权限；只匹配 x.com / twitter.com）
src/dom.js            帖子容器、Grok 入口、永久链接提取
src/composer.js       抽屉开关、输入框定位、稳定写入
src/content.js        点击拦截与分流
src/background.js     /i/grok 跳转时的待填文本传递
src/options.html|js   设置页（尾随空格开关）
icons/                图标
```

## 已知限制

- X 改版就可能失效。已内置两级兜底：找不到悬浮按钮 → 新标签页打开 `/i/grok`；找不到入口 → 完全不干预（不会破坏原网站行为）。
- 界面语言无关（按 `aria-label` 匹配，已覆盖中/英文）；若 X 换成没有可访问名称的纯图标按钮，需要按它的 `data-testid` 补一条匹配。
- 桌面端打开的是 X 自己的抽屉，因此样式与交互跟随 X 的版本变化。
